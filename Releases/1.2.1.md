# Pet's Pet 1.2.1

日期：2026-10-16。基于用户确认的 1.2.0 外观，仅修复重启连接和诊断信息。本次真实 Codex 重启恢复已由用户实测确认，发布后验收记录见下文；连续多轮重启及其他未测场景仍单独保留边界。

## 问题与证据

- 用户实测：重启 Codex 后，宠物本体已显示，额度组件不显示；辅助功能授权仍有效，额度查询仍成功。
- 系统元数据确认新 Codex 主进程和可见宠物浮层存在。1.2.0 在相同条件下只扫描到 7 个节点，未找到宠物。
- 本机 Codex Framework 包含 Chromium 的 `AXEnhancedUserInterface` 标记，没有检索到 Electron 的 `AXManualAccessibility` 标记。1.2.0 忽略了激活接口返回码，不能据此判定连接成功。
- 1.2.0 在 AXWindows 调用成功时就清除恢复状态，空数据或未就绪结构可能被误认为正常等待。

## 修复

- 读取应用标准可访问角色；优先尝试 Electron 的轻量激活方式，不支持时检查 Chromium 的激活属性是否已开启或可设置，再按支持情况处理。
- 成功激活按 Codex 进程记录，仅执行一次；不关闭该属性，不重置 VoiceOver，不发送键鼠事件，不修改系统授权、客户端文件或登录配置。
- 对成功但结构尚未就绪的查询继续采用有限频率重连；没有可见浮层时允许正常等待宠物。扫描只针对浮层，不读取主窗口聊天内容。
- 诊断增加进程、系统窗口数、AX 窗口数和两种激活返回码；状态不变时每 10 秒更新一次当前诊断，避免旧文件被当作当前状态。状态变化事件仍限频并按原规则轮转。

## 文件

- `Sources/PetsPet/PetMonitor.swift`：激活协商、就绪判断与诊断字段。
- `Sources/PetsPetCore/MonitorRecovery.swift`：空结构继续恢复的判定。
- `Sources/PetsPet/AppDelegate.swift`：诊断变化记录和心跳。
- `Tests/PetsPetCoreTests/PetsPetCoreTests.swift`：空／不完整结构、成功读取、进程再次切换的恢复检查。
- `Resources/Info.plist`、`README.md`、版本索引与更新日志。

## 验证和限制

- 22 组、105 项规则断言通过，生产构建和隔离候选包签名校验通过。此前通过的图标及样式预览保持不变，没有重复改动。
- 打包、源码与哈希通过发布脚本校验后留存到 `dist/releases/1.2.1/`，再同步固定入口及 Next。1.2.0 的历史包保留。
- 此版本使用本机临时签名；更新后是否沿用授权以系统实际状态为准。
- Chromium 激活采用其现有辅助技术接口，启动可能有异步延迟；其他客户端版本、输入行为、睡眠、多屏／桌面切换仍需实测。只有当前连接成功不能证明真实重启已修复。

## 发布后实际验收（2026-10-16）

- 用户确认：“重启后展示了，没问题了”。本次 Codex 重启后的自动恢复验收通过。
- 本地记录相互印证：北京时间 21:29:28 检测到 Codex 退出；重启后检测到新的 Codex 进程；21:29:38 恢复到唯一宠物、组件可见和正在跟随状态；随后额度状态为可用。
- 本次只补充验收记录，没有重建或重新签名应用。保留现有 1.2.1 安装包及源码快照。
- 本次为一轮实际重启恢复，连续多轮重启、其他客户端版本、睡眠与多屏／桌面切换不据此视为通过。

## 实测步骤

1. 新版授权有效、宠物本体已显示时，检查额度组件和最近诊断是否恢复，激活返回码是否正常。
2. 等当前 Codex 任务结束后，保持 Pet's Pet 运行，退出并重新打开 Codex，再显示宠物，等待自动检测。
3. 返回当前聊天反馈结果，检查日志是否同时记录新的 Codex 进程和唯一宠物、可见组件。成功后再重复一次，不要求重启 Pet's Pet。
4. 确认 Codex 普通键盘输入、拖动和窗口行为无异常。
